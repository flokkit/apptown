Maven's versions plugin moves the parent, version properties and explicit
versions to their newest releases and skips pre-releases. Routine updates stay
within each major; aggressive updates take majors. A targeted fix moves only
the named artifacts' own versions: one only the parent manages stays where it
is and the fix is refused. A parent update that adds or removes an artifact,
or moves one past the routine bound, is refused too. `java.version`, the
toolchain and the Dockerfile are never changed.

The listing maps Maven versions onto semver: `.Final`, `.GA` and `.RELEASE`
are the release; anything after the third number is kept as build metadata
(`1.9.25.1` lists as `1.9.25+1`), so an update that moves only that part is
refused. A pre-release (alpha, beta, milestone, RC, CR, snapshot) cannot be
listed. Each artifact's source is the URL of the repository it came from.
Only a single-module build can be listed: a reactor with modules fails the
listing rather than report one module's dependencies as the whole app's.
