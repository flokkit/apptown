# The command line's JSON

The core-loop commands (`new`, `fix`, `quick`, `plan`, `build`, `land`,
`show`, `changes`, `wait`, `approve`, `release`, `rollback`, `complain` and `version`)
take `--json`. A script reads these fields; they are stable through 1.x, as
[What 1.0 promises](compatibility.md) says. A field may be added;
none is renamed or removed. A field whose values are listed below (a
`state`, an `outcome`) may gain values: treat one you do not know as "look at
the change", never as success.

With `--json` a command:

- prints one JSON document on standard output and nothing else there; what it
  says along the way, and any error, goes to standard error;
- never follows a run and never asks a question: `fix`, `quick`, `plan`,
  `build`, `land` and `release` return once AppTown has accepted the
  request, and `approve` needs `-y` (read what approving means first:
  `apptown approve <step>` prints it, and without a terminal approves nothing);
- ends with the exit code it has without `--json`. `wait` prints its document
  for every outcome it waited to, including the ones that exit non-zero. A
  command that fails before it has an answer (a record that does not exist, an
  AppTown out of reach, a refusal) prints no document and says why on standard
  error, with the exit code it has without `--json`: 64 when the command line
  was wrong (no change was sent), 69 when AppTown could not be reached, 4 when
  a change was sent but the answer was lost, and 1 otherwise.

A change or run is named by its UUID (`id`) and its number within its project
(`number`); a change also by `name`, the `slug#number` you can type anywhere
the CLI takes a change, `apptown wait` included (there that form always
names a change; a run is given by its `id`). For example:

```sh
change=$(apptown quick -p shop --json "add a footer" | jq -r .change.id)
apptown wait -c "$change" --json > outcome.json
case $? in
  0) echo shipped ;;
  2) step=$(jq -r '.step // empty' outcome.json)
     [ -n "$step" ] && apptown approve "$step" -y --json ;;
  *) jq -r .detail outcome.json ;;
esac
```

`apptown wait --json` does not cover a release (`-r`); follow one with
`apptown wait -p <slug> -r <number>` and its exit code. Inside a change's chat,
`apptown land` (bare, or naming that chat's own change) answers in words only;
with `--json` it refuses before starting anything.
