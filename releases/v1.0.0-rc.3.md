# Flokkit v1.0.0-rc.3

The third candidate for Flokkit 1.0. It corrects the recovery rehearsal's
cleanup lock handling so the full ownership identity survives the SSH command
boundary and a failed lock release cannot be reported as successful cleanup.
RC2 passed its fresh-install rehearsal and source deployment; its recovery
copy was interrupted before restore startup. Subsequent cleanup exposed this
script defect. RC1 and RC2 remain unchanged.

The compatibility promises and experimental boundaries remain in
[What 1.0 promises](https://github.com/flokkit/apptown/blob/main/stock/docs/guides/compatibility.md). The one-time
identity conversion applied to the maintainers' pre-1.0 installations; a new
install starts at the 1.0 baseline.

Deployment policy remains `compatible-update`. `protected-maintenance` is
reserved and refuses requests with “not implemented” before deployment effects.
Automatic recovery is not implemented. Recorded deployment limits are preserved
on rebuild; new deployments resolve explicit overrides and declarations before
adopted or platform defaults. Provider-managed sizes remain separate.

## HTTP API changes

No route or schema changes since `v1.0.0-rc.2`. The API remains experimental;
the served description is `/api/v1/openapi.json`. Resource/profile and
capacity routes are listed, while their request and success-body schemas remain
unmodeled; the resource and deployment guides describe their behavior.

## Deprecations

None.
