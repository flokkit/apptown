# Flokkit AppTown v1.0.0-rc.17

RC17 is about backups that work on Portainer and pages that answer their
question first. Backups of deployments on a Portainer target work again with
Portainer 2.45, and the Backups page now lists each deployment that holds
data with whether it is safe and a Back up now for one in trouble. Chats
stream the helper's words as it writes them and read as one thread on a
phone. Deployment protection is now an explicit setting, and the Janitor's
Including major level moves a major version only when it is due. It
includes all changes since RC16. Some changes are breaking; read "Breaking
changes" before upgrading. Take matching database and file backups before
upgrading, as described in the
[upgrade guide](https://github.com/flokkit/apptown/blob/main/stock/docs/guides/upgrading.md).

## Breaking changes

Before upgrading:

- **Upgrade AppTown and its workers together.** Chats on a worker now
  stream, which changes the worker protocol to 5. A worker of this release
  serves protocol 5 only, so an AppTown and worker of different releases
  refuse each other. **Operator step:** stop AppTown and its workers,
  upgrade both, then start them. An installation without a worker has
  nothing to do.

After upgrading:

- **Protected deployments wait for a person.** Protection is now a stored
  setting on each deployment (migration 246), under the deployment's
  Releases settings. A deployment keeps the protection it had: on for a
  public or partners audience or production data. Changing audience or data
  no longer changes it. Every automatic release to a protected deployment,
  including a landing on a deployment that follows main and a Janitor
  update, waits for a person with release rights; a release such a person
  requests runs directly. While a deployment is protected, Needs approval
  and Janitor releases are hidden. Turning protection off needs deploy and
  release rights and the person's own assent to the sentence shown, which is
  recorded. **Action:** if a deployment should take landings without a
  person, turn its protection off in Settings › Releases.
- **The Janitor's Including major level moves a major only when it is
  due:** when the current major ends support within three months (or
  already has), when a scan finding is fixed only on a newer major, or when
  the newest major has been out at least six months with at least two
  releases after it. Otherwise the package gets patch and minor updates.
  Languages and runtimes that
  [endoflife.date](https://endoflife.date) tracks (PHP, Python, Node, Go,
  Postgres, Django and others) move by release line: PHP 8.3 to 8.5 is a
  major move under these rules, not a minor one. A fact AppTown cannot read
  never allows a move.
- **A chat already running when AppTown restarts** shows "Working…" until
  its helper next stops and starts again; on a worker it also saves no turns
  until then.

## New and improved

Backups and deployments:

- **Backups through Portainer 2.45.** Copies mount the service's volumes by
  name instead of `--volumes-from`, which Portainer now refuses to a regular
  user, and a container start through Portainer sends a body Docker accepts.
  Portainer's reason for a refusal shows in the message.
- **Portainer releases wait for the stack.** When Portainer accepts a stack
  while Compose is still running, AppTown waits up to 90 seconds for its
  result: an active stack confirms the release, a failed one fails it with
  Portainer's message, and an unresolved one stays unknown.
- **Disk readings through Portainer.** The disk reader no longer binds the
  host's Docker folder, so a Portainer target's disk is read instead of
  "unknown".
- **Backups page.** One row per deployment that holds data, problems first:
  backed up, overdue, no copy yet, unknown or restoring, with the reason,
  the newest copy's time and size, and Back up now on a row in trouble.
  Beside the rows: the store, how many deployments got a complete nightly
  copy in the last day, and the last restore.
- **Deployment page.** The Status tab leads with what the deployment is
  doing and one row per problem with the act that fixes it, beside a facts
  card and its containers. Each container has its own page, naming the
  registry, repository and digest of a release image when the host confirms
  it is the one running. An app that stopped by itself is offered Start.
- **Static apps no longer need `staticServer:`.** Without a pin, a static
  part is served with the newest `caddy:2-alpine` build, read when a build,
  preview or compose export starts, and the release records the image it
  used. A pin is honoured and the Janitor keeps moving it. RC16's one-time
  step of adding a pin to each static project is no longer needed.
- **Restore** accepts an AppTown backup taken while a task finished; that
  task ends as interrupted.

Chats and changes:

- **Chats stream.** The helper's words appear as it writes them, one word
  behind, over one event stream per open chat, and "Working…" clears as
  soon as the helper hands back. Text still being written never reveals
  anything about a secret.
- **Chat as a thread.** The project chat and the change's Conversation tab
  show one bar, one line per run of tool steps (the steps open beside the
  chat or in a sheet), and an input that grows. The chat menu offers Abandon
  change….
- **An idle change says "draft"**, not "building"; "building · helper
  working" shows only while its helper is replying.
- **One bar at the top of every page**, list rows open by clicking the row,
  and phone record rows keep a status on its label's line.

Checks and the agent image:

- **An AppTown that builds its own agent image rebuilds it** when the
  release's recipe differs, keeping the old image until the new one is
  ready. Before this, an upgraded installation could keep an old agent
  whose model checks all failed.
- A check agent that fails names its exit status and its last error line,
  and a check that could not be assessed reads "unknown".
- A Docker Hub mirror that asks for a token passes its connection check.

Fixes:

- Cancelling a local run reaches a child process forked while the run was
  being stopped, so it no longer waits a minute.
- A closed change keeps its description after later steps finish, and image
  scan notes count each finding once.

## Declaration changes

- `.apptown/app.yaml`: `staticServer` is optional again (see above).

## HTTP API changes

These changes are relative to RC16. The HTTP API remains experimental. The
[OpenAPI description](https://github.com/flokkit/apptown/blob/main/stock/docs/api/openapi.json)
contains the available route definitions.

- Added: `GET /api/v1/backups/deployments`, one row per deployment that
  holds data with its backup state.
- Added: `GET /api/v1/console/{sid}/stream`, the chat's Server-Sent Events
  stream.
- Added: `PUT /api/v1/projects/{slug}/deployments/{name}/protected` (body
  `ProtectedSettings`: `protected`, `meaning`, `was`).
- Added: `GET /api/v1/runs/{id}/major-moves`, the major moves a Janitor run
  considered and why each was allowed or not.
- Changed: `Deployment` adds `protected` and `protectedReason`;
  `DeploymentView` adds `protectedReason` and `unprotectMeaning`.
- The worker protocol is 5 (see Breaking changes). The CLI protocol is
  unchanged.
