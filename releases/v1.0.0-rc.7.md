# Flokkit AppTown v1.0.0-rc.7

Draft: the notes for the next release candidate, written as changes land.

## What changed

### Removed

- **Moving a deployment made before 1.0 to its new names.** Every
  deployment is now named by its key. `apptown move-names` and its route
  are gone, and so is everything that still read the names and `forge.*`
  labels things had before 1.0: the start-up sweep of what an AppTown before
  1.0 left on its Docker, the old label reads, and the `forge-` prefix in
  the readers of names on a host. A built-in database container that does
  not carry this installation's `apptown.instance` label is refused, as its
  volume already was.

## Upgrading from RC6

Every deployment must be named by its key before the upgrade. Migration
167 stops the upgrade, changing nothing, while a deployment still holds a
container, a Portainer stack or anything else on a host under the names it
was made with, and names each one. Under RC6, move one on a Docker host
with `apptown move-names`; take one on Portainer down and release it again
(its data is not carried over: copy it first). See the upgrading guide.

### Database migrations

167: the recorded host prefix of each deployment and the move flag on
release requests are dropped, once no deployment is still on its old names.

## HTTP API changes

Routes removed:

- `POST /api/v1/projects/{slug}/deployments/{name}/move-names`, added in
  RC6 and not promised.
